# วิธีเพิ่มและแก้เนื้อหา

มีสองทาง: แก้ผ่านหน้าจอ `/admin` (สำหรับเจ้าหน้าที่ตำหนัก)
หรือแก้ไฟล์ตรง ๆ (สำหรับผู้ดูแลระบบ) ทั้งสองทางเขียนลงไฟล์ชุดเดียวกัน

## ลงข่าว

`/admin` › ข่าวสารและประกาศ › New
หรือสร้างไฟล์ `src/content/news/2026-11-01-ภาพงานกินเจ.md`

```yaml
---
title: ประมวลภาพเทศกาลกินเจ
date: 2026-11-01
summary: บรรยากาศช่วงเทศกาลกินเจที่ตำหนัก
cover: ""
pinned: false
---

เนื้อหาข่าว…
```

ข่าวที่เก่ากว่า ๖ เดือนจะหายจากหน้าแรกเอง (ยังอยู่ในหน้า `/news`)
ปรับจำนวนเดือนได้ที่ `content.news_stale_months` ใน `src/data/site.json`
ทำแบบนี้เพื่อไม่ให้หน้าแรกโชว์ข่าวค้างปีถ้าไม่มีใครลงข่าวต่อ

## เนื้อหา ๓๓ ปาง มาจากไหน

ต้นฉบับอยู่ที่ `content-src/guanyin-33-pang-th-v3.md` (~๗๔,๖๐๐ คำ มีเชิงอรรถ ๘๒ รายการ)

```bash
npm run import:book
```

สคริปต์จะ
1. อ่านตารางเทียบชื่อ → `name_th`, `name_th_scholarly`, `name_zh`, `name_zh_variants`
2. อ่านตารางสรุป → `attributes` (เครื่องหมายที่ใช้จำ) และ `essence` (แก่นของปาง)
3. ตัดบททั้ง ๓๓ ไปไว้ที่ `src/content/pang-full/` พร้อมยกนิยามเชิงอรรถที่บทนั้นใช้มาท้ายบท
4. ใส่ย่อหน้าแรกของบทเป็นเนื้อหาหน้าปางฉบับย่อ

**สคริปต์ไม่แตะช่องที่ตำหนักเป็นเจ้าของ** — `name_th_shrine`, `enshrined`, `incense`,
`wishes`, `verified_by` เพราะหนังสือไม่ใช่ผู้รู้เรื่ององค์ที่ประดิษฐานอยู่จริงในตำหนักนี้

อัปเดตต้นฉบับแล้วรันใหม่ได้เสมอ ผลลัพธ์จะทับของเดิมเฉพาะช่องที่หนังสือเป็นเจ้าของ

## หน้าปางมีอะไรบ้าง

หน้าปาง `/33-pang/<slug>` เป็นหน้าเดียวต่อปาง บทเต็มที่เคยแยกอยู่ `/33-pang/<slug>/full`
ยุบมารวมแล้ว ที่อยู่เดิม redirect มาหน้าหลักใน `vercel.json`

| ส่วน | มาจากช่อง | แสดงเมื่อ |
|---|---|---|
| ชื่อ แก่นของปาง ลักษณะเด่น สรุปสั้น | หนังสือ (`import:book`) | เสมอ |
| องค์ที่ตำหนักผู่โถว | `posture` `holds` `base` `material` `height_cm` `maker` `donor` `shrine_statue` `shrine_highlight` + ภาพ `photo_detail` `photo_place` | มีอย่างน้อยหนึ่งช่อง |
| ขอพรปางนี้อย่างไร | `how_to_ask` + `short_prayer` + `prayer` | มี `how_to_ask` |
| ความหมายและเรื่องเล่า | บทเต็มใน `src/content/pang-full/` | เสมอ |
| ปางที่มักสับสนกัน | `confused_with` | มีข้อมูล |
| กราบแล้วไปต่อที่ปางใด | `see_also` | มีข้อมูล |
| ถามสั้น ตอบสั้น (+ FAQPage ให้ Google) | `faq` | มีข้อมูล |

สองส่วนแรกของตำหนัก (องค์จริง และขอพร) ติดป้าย "รอตำหนักยืนยัน" จนกว่า `verified_by` จะมีชื่อ

บทเต็มที่เรียบเรียงขยายด้วยมือแล้ว ให้ใส่ `edited: true` ในไฟล์ `pang-full`
ไม่งั้น `npm run import:book` รอบหน้าจะเขียนทับงานที่ขยายไว้

## แบบฟอร์มข้อมูลองค์จริง

ตำหนักกรอกข้อมูลองค์จริงใน Google Sheet แบบฟอร์มสร้างจากข้อมูลปางปัจจุบัน
(แท็บ "วิธีกรอก" + แท็บ "ข้อมูลองค์จริง" 33 แถว) อัปโหลดเข้า Google Sheets ด้วย
ไฟล์ › นำเข้า › อัปโหลด

หัวคอลัมน์เป็นภาษาไทยพร้อมชื่อช่องในวงเล็บ เช่น `ความสูง เซนติเมตร (height_cm)`
สคริปต์นำเข้าอ่านชื่อในวงเล็บ คอลัมน์ `ref_*` `notes` `filled_by` ไม่ถูกนำเข้า
ช่องว่างไม่ลบข้อมูลเดิม เรื่องที่ขอกรอกเป็นชื่อไทยได้ (สุขภาพ คลายทุกข์ …)
บทสวดเลือกจากชื่อไทย (มหากรุณาธารณี สมันตมุขปริวรรต หกพยางค์ ไม่มีเฉพาะ)
อักษรจีนที่ฐานองค์ ถ้าไม่ตรงกับ `name_zh` จะถูกเก็บเป็นชื่ออื่นที่พบ

นำเข้าเหมือนเดิม — ดูก่อนด้วย `--dry` แล้วค่อยเขียนจริง

## แก้ข้อมูลปาง

ปกติกรอกใน Google Sheet แล้วรัน

```bash
npm run import:sheet -- "https://docs.google.com/.../pub?output=csv" --dry   # ดูก่อน
npm run import:sheet -- "https://docs.google.com/.../pub?output=csv"         # เขียนจริง
```

สคริปต์จะทับเฉพาะช่องที่กรอกมาใน Sheet ช่องที่เว้นว่างจะไม่แตะ
และ**ไม่แตะคำอธิบายยาว** ที่เขียนไว้ใต้ frontmatter ในไฟล์

แก้ทีละองค์ทำได้ที่ `/admin` › ๓๓ ปาง หรือแก้ไฟล์ `src/content/pang/01-yang-liu.md` ตรง ๆ

### ฟิลด์ที่ต้องระวัง

| ฟิลด์ | ข้อควรระวัง |
|---|---|
| `slug` | **ห้ามเปลี่ยนหลังพิมพ์ป้าย QR แล้ว** — ป้ายชี้มาที่ค่านี้ |
| `verified_by` | เว้นว่าง = ไม่เผยแพร่คำอธิบายยาว และไม่ให้ Google เก็บดัชนี |
| `name_th_shrine` | ใส่เมื่อป้ายในตำหนักใช้ชื่อไม่ตรงกับชื่อทั่วไป — เว็บจะแสดงชื่อนี้แทน |
| `enshrined` | `false` = ยังไม่ได้อัญเชิญมา แสดงเป็น “กำลังอัญเชิญ” |
| `wishes` | เลือกได้ ๑–๓ หมวด ถ้าใส่เกิน ๓ แปลว่ายังไม่ได้คิดจริง |

## ปฏิทินวันสำคัญ

แก้ที่ `/admin` › ปฏิทินวันสำคัญ หรือไฟล์ `src/content/events/2569.yaml`

ร่างวันของปีใหม่ด้วย

```bash
npm run lunar -- 2028
```

แล้ว **เทียบกับปฏิทินจีนฉบับพิมพ์ (通勝) หรือปฏิทินที่ตำหนักใช้**
ก่อนตั้ง `approx: false` — วันที่ยัง `approx: true` จะแสดงเครื่องหมาย `≈` บนเว็บ
พร้อมคำอธิบายว่าอาจคลาดเคลื่อนหนึ่งวัน

> สคริปต์คำนวณจากรอบจันทรคติจริง (UTC+8) ตรวจแล้วว่าให้ตรุษจีน ๒๕๖๙ = 17 ก.พ.
> และวันประสูติ = 6 เม.ย. ตรงกับปฏิทินทั่วไป แต่บางวันอาจต่างกันหนึ่งวัน
> จึงยังต้องให้คนตรวจก่อนเสมอ

## ภาพถ่าย

วางไฟล์ใน `photos-src/` ตามชื่อที่กำหนด แล้ว

```bash
npm run images   # ย่อเป็น WebP ๓ ขนาด + อัปเดต src/data/photos.json
npm run og       # สร้างภาพพรีวิวตอนแชร์ใหม่
```

หน้าปางจะเปลี่ยนจากภาพแท่นบูชาเป็นภาพจริงเองทันทีที่ไฟล์มา
ไม่ต้องแก้โค้ดหรือแก้ข้อมูลปาง

## ป้าย QR

```bash
npm run qr        # → dist-qr/qr-sheet.html
```

เปิดในเบราว์เซอร์ › สั่งพิมพ์ › บันทึกเป็น PDF
พิมพ์ขนาดจริงอย่างน้อย ๓×๓ ซม. ติดที่ฐานองค์ระดับสายตา
**ทดสอบสแกนทุกชิ้นก่อนติดจริง**

ทุกลิงก์มี `?src=qr` ต่อท้าย ไว้นับว่าคนเข้าเว็บจากป้ายในตำหนักมากแค่ไหน
ถ้าเกิน ๒๐% ของทราฟฟิกหน้าปาง แปลว่าตำหนักเป็นช่องทางหลักจริง

## เพิ่มหรือแก้ภาษาจีน

ข้อความ UI (เมนู ปุ่ม ป้ายกำกับ) อยู่ที่ `src/i18n/index.ts` — แก้ที่ `ZH`

ข้อความจีนของแต่ละปางอยู่ที่ `src/content/pang-zh/pang-zh.yaml`
มีสองช่องต่อหนึ่งปาง: `marks` (辨識標記) และ `essence` (本願要旨)
ชื่อจีนไม่ได้อยู่ในไฟล์นี้ เพราะอยู่ใน `name_zh` ของ `src/content/pang/` อยู่แล้ว

หน้าเว็บภาษาจีนอยู่ที่ `src/pages/zh/` เขียนเนื้อหาตรงในไฟล์ ไม่ได้ดึงจากไฟล์แปล
เพราะเป็นเนื้อหาที่เขียนขึ้นสำหรับผู้อ่านจีนโดยเฉพาะ ไม่ใช่คำแปลตรงตัวของฉบับไทย

**เพิ่มหน้าจีนใหม่** — สร้างไฟล์ใน `src/pages/zh/` แล้วเพิ่ม path ฝั่งไทยลงใน
`TRANSLATED_ROUTES` (`src/i18n/index.ts`) ปุ่มสลับภาษาและ `hreflang` จะทำงานเอง

> คำแปลจีนชุดปัจจุบันแปลจากต้นฉบับไทย **ยังไม่ได้ผ่านผู้รู้ภาษาจีน**
> ควรให้ตรวจก่อนประกาศเป็นทางการ โดยเฉพาะศัพท์เฉพาะทางพุทธศาสนา
